创建测试集和测试数据

LLM 测试数据是一条可执行的自动化用例。它至少需要包含用户完整输入和与场景匹配 的预期结果；如果用例依赖企业数据、人员或附件，还需要在测试用户或测试场景中 准备相应的运行上下文。

选择创建方式

方式一：先创建测试集，再创建测试数据

适合已经知道用例归属范围，或者需要持续向同一个测试集补充用例的场景。

操作路径：

  1. 打开 AI 工作台中的 Agent 评测。

  2. 进入 LLM 测试集。

  3. 新建测试集并填写测试集名称。

  4. 在测试集下新建 LLM 测试数据。

  5. 保存后检查测试数据是否出现在目标测试集下。

方式二：单独创建测试数据

适合先调试一条用例，之后再决定是否加入测试集。

操作路径：

  1. 进入 LLM 测试数据。

  2. 点击“新建”。

  3. 填写测试数据字段。

  4. 需要归组时，选择关联测试集或多选测试集。

  5. 保存后先执行单条用例验证配置。

主要字段

字段

填写内容

注意事项

name

用例名称或验证点描述。

建议使用“标签 + 验证目标”的格式，例如“更新联系人手机号并回查”。

classification__c

业务分类。

常见值为 Agent、Skill、RAG、Prompt，以当前选项配置为准。

Agent 名称

关联的 Agent 名称或 API 名。

使用当前环境的实际配置值。

Skill 名称

目标 Skill 名称或 API 名。

只有 Skill 类用例需要填写。

wholeBody__c

发给 Agent 的完整输入 JSON。

原始用户问题放在 user_input，多轮和交互字段按输入主题配置。

expected_result__c

校验器使用的预期结果 JSON。

它描述如何校验，不是发给 Agent 的用户问题。

llm_dataset__c

关联的单个测试集。

适合用例只有一个归属测试集的情况。

test_set_multiple_choice__c

关联的多个测试集。

一个用例可同时属于多个测试集。

推荐的命名方式

用例名称应能让执行人快速知道动作和验证点：

创建客户并校验客户名称 更新联系人手机号并确认目标记录 查询未来一天的日程并校验参与人 统计本月商机金额并校验聚合结果

不要只写“测试 1”或“新建 case”，否则任务失败后难以定位用例意图。

wholeBody__c 的最小输入

在 LLM 测试数据中，wholeBody__c 保存为 JSON 文本。最小结构如下：

{ "user_input": "帮我创建一个客户，名称是${random:company}" }

如果需要回答 Agent 的交互问题，可以在同一个 JSON 中增加 question_answers； 具体写法见 输入、附件和变量。

expected_result__c 的最小输入

预期结果至少要能说明校验类型。创建场景可以从一个关键字段开始：

{ "validate_type": "create", "object_api_name": "AccountObj", "required_fields": [ { "api_name": "name", "value": "${random:company}", "field_type": "text", "match_mode": "exact" } ], "optional_fields": [] }

复杂场景不要把所有规则堆在一行；按 编写预期结果 中的场景类型 选择结构，并在保存前检查 JSON 是否完整。

分类和关联检查

  • classification__c 决定用例属于哪类评测，不能只根据用例名称猜测。

  • Agent 或 Skill 名称要与当前环境的配置一致。

  • 单条用例先独立执行，确认结果后再加入批量测试集。

  • 同一条用例放入多个测试集时，确认这些测试集的测试用户、变量和执行目标兼容。
