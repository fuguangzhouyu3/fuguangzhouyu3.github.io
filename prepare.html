ShareAgent 自动化用例录入指南 Help

准备环境和入口

开始录入前，需要确认当前企业具备 Agent 评测权限，并准备好执行用的测试用户、 测试环境地址和业务变量。环境相关值不要直接从其他企业复制。

检查项

企业

当前登录的 fs 企业是目标测试企业。

权限

账号可以打开 AI 工作台和 Agent 评测。

Agent

评测用的 Agent 名称和 API 名已确认。

测试用户

已配置登录信息、企业信息和访问地址。

测试数据

需要复用的记录、人员和部门已经准备好。

附件

附件场景的文件已上传到执行环境。

打开 Agent 评测

在 fs 企业中按以下路径进入：

fs 企业 -> AI 工作台 -> Agent 评测

如果左侧导航栏没有 AI 工作台，可以使用以下方式调整导航：

  1. 从左侧导航栏打开“更多”。

  2. 进入“导航设置”。

  3. 打开“应用显示”。

  4. 找到 AI 工作台，并将其移动到主导航。

配置 LLM 测试用户信息

进入：

AI 工作台 -> Agent 评测 -> 其他 -> LLM 测试用户信息

至少确认以下信息：

配置

说明

企业和用户

测试请求实际使用的企业与用户。不同用户可能有不同的数据权限。

baseurl

测试账号所在 fs 环境的访问域名。

Agent 标识

需要执行的 Agent API 名或产品配置名称。

登录信息

按当前系统要求配置，不要将密码、Cookie、Token 或验证码写入用例。

baseurl 应填写当前环境的访问域名，例如：

www.fxiaoke.com

测试环境可能使用其他域名，例如：

crm.ceshi112.com

上面的域名只是写法示例，实际值以测试账号所在环境为准。

准备业务变量

业务变量是测试执行时的运行上下文和数据夹具，适合保存不会写死在每条用例中的 记录和人员信息。

一个最小的对象变量示例：

{ "object_data": { "AccountObj": [ { "id": "replace-with-current-account-id", "name": "当前企业的测试客户" } ] }, "employee_data": [ { "id": "replace-with-current-employee-id", "name": "当前测试人员", "user_name": "current_test_user", "is_current": true } ] }

跨企业复用

同一条用例需要在多个企业执行时，用 data_key 保存稳定的业务含义；每个企业 分别维护自己的记录 ID 和展示名称。

{ "data_key": "sales_followup_record", "id": "enterprise-specific-record-id", "name": "enterprise-specific-record-name" }

更新已有记录

更新场景通常有两个不同需求：

  • 给 Agent 的输入：使用用户能看懂的记录名称、编号或主题。

  • 校验目标：使用业务变量解析出的记录 ID，确认更新的是指定记录。

不要把一个企业里的真实记录 ID 直接复制到另一个企业的用例中。
