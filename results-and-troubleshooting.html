查看结果和排查失败

执行评测后，从 Agent 测试任务查看任务状态、用例结果和执行明细。排查时不要只看 最终总分；应先确定失败发生在输入、Agent 规划、工具执行、业务结果、落库回查还是 评估规则。

打开任务结果

进入：

AI 工作台 -> Agent 评测 -> Agent 测试任务

打开目标任务后，重点查看：

  • 任务整体状态和完成时间。

  • 每条测试数据的通过/失败状态。

  • Agent 最终回复文本。

  • 实际调用的工具、Skill、子 Agent 和循环次数。

  • 结构化业务结果或卡片内容。

  • CRM 回查结果以及目标记录 ID。

业务校验

创建、更新、查询或分析结果是否满足预期？

不能证明工具路径一定符合要求。

工具调用校验

是否调用了预期工具、Skill、子 Agent 和循环次数？

不能证明 CRM 已真实落库。

对于更新和创建场景，还要单独确认：

  • Agent 是否选择了正确对象。

  • 工具入参中的记录 ID 是否是目标记录。

  • 页面卡片或结构化结果是否写入成功。

  • CRM 回查是否读到了预期字段。

“任务完成”“Agent 成功”“HTTP 200”“最终文案正确”都是独立信号，不能相互 替代。

推荐排查顺序

1. 确认执行输入

查看 wholeBody__c 的实际内容：

  • user_input 是否完整。

  • question_answers 的 key 是否使用 input_api_name。

  • 附件路径是否存在于执行环境。

  • 用户问题中是否误用了另一个企业的 ID。

2. 确认变量解析

检查：

  • obj_data 的对象 API 名和变量 key。

  • employee_data 的当前用户标记。

  • 变量池 label/value 是否指向当前企业数据。

  • random、time 和 pool 变量在输入与预期结果中是否复用一致。

3. 确认预期结果 JSON

检查：

  • validate_type 是否与操作一致。

  • create/update 是否选择了正确的对象结构。

  • update 是否提供 data_id。

  • query 的过滤字段和时间范围是否正确。

  • aggregation 是否填写了正确的 agg_type 和 agg_field。

  • expected_agents 是否使用当前版本支持的键。

4. 确认真实业务结果

更新或创建用例优先查看结构化结果和 CRM 回查；查询用例比较返回记录集合； 聚合用例确认统计范围和聚合接口，而不是只看 Agent 的一句总结。

5. 最后分析过程证据

当业务结果不符合预期时，再分析工具调用、Skill、子 Agent 和 loop.total，判断 是 Agent 路由、参数、恢复行为还是预期配置导致偏差。

常见问题

现象

优先检查

用例保存失败

JSON 是否闭合，字段名和类型是否符合表单要求。

Agent 找不到记录

输入名称是否正确，当前企业是否准备了对应业务变量。

更新到了错误记录

expected_result__c 的 data_id 和输入中的记录名称是否对应。

创建结果名称重复

输入是否使用 random:company 或其他唯一变量。

日期校验失败

输入和校验是否引用同一 random/time 变量，时间格式是否匹配字段类型。

多选人员校验失败

输入使用 labels_joined，校验是否使用 values，数组是否指向正确人员。

附件读取失败

文件是否真的上传到 /opt/data/，storage_path 是否为容器内路径。

聚合结果异常

查询范围、对象 API 名和 QueryRecordsAggregateBySQL 路径是否准确。

工具得分异常

expected_tools 的名称、action 和当前真实调用结构是否一致。

子 Agent 校验被跳过或不匹配

优先使用 expected_agents，并核对兼容键和部署版本。

结果记录模板

排查失败用例时建议记录：

用例： 任务： 输入是否正确： 变量是否解析： 预期结果是否可解析： 实际工具调用： 业务结果： CRM 回查： 首次偏差： 后续处理：

“首次偏差”应记录最先与用例契约不一致的步骤，不要只抄最终分数。

提交前检查清单

  • [ ] 用例在目标企业单条执行过。

  • [ ] 关键字段已通过结构化结果或 CRM 回查确认。

  • [ ] 查询/聚合用例的过滤范围可复现。

  • [ ] 预期工具和 Skill 是根据实际链路填写，而不是根据名称猜测。

  • [ ] 失败时能够区分 Agent 问题、数据夹具问题和评估配置问题。

  • [ ] 外部环境依赖已经在用例说明或测试场景中明确。
