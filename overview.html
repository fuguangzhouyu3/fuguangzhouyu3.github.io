ShareAgent 自动化用例录入指南

本指南用于说明如何在 fs 企业中录入、执行和核对 ShareAgent 自动化评测用例。 内容覆盖从测试数据准备到任务结果分析的完整闭环，适合用例作者、评测执行人和 负责复核结果的同学使用。

重要 ：示例中的企业、人员、记录 ID、文件名和时间值只用于说明结构。录入前 必须替换为当前企业和当前环境中的真实值。

录入闭环

  1. 准备 fs 企业、Agent 评测权限、测试账号和业务变量。

  2. 创建测试集和 LLM 测试数据，填写用户输入与预期结果。

  3. 按场景需要配置随机变量、时间变量、变量池和 data_key。

  4. 选择用例、测试集或测试场景执行评测。

  5. 在 Agent 测试任务中查看执行状态、校验结果和工具调用明细。

  6. 对失败结果回到输入、变量、预期结果和真实数据逐层核对。

先理解这几个对象

名称

作用

测试数据

一条可执行的自动化用例，保存用户输入和预期结果。

测试集

一组可批量执行的测试数据。

测试场景

按业务目标组织测试集并生成评测任务的执行入口。

测试任务

一次实际执行的任务，包含状态、结果和诊断信息。

业务变量

随环境变化的记录、人员和上下文数据。

变量池

可供输入和预期结果动态取值的标签/值集合。

预期结果

告诉校验器如何验证业务结果、工具、Skill 和子 Agent。

最短可用路径

首次录入建议先做一条最小用例：

  1. 在 AI 工作台打开 Agent 评测。

  2. 新建一条 LLM 测试数据。

  3. 在 wholeBody__c 中填写一个明确的用户问题。

  4. 在 expected_result__c 中填写一种校验类型和一个关键校验字段。

  5. 直接执行单条用例。

  6. 打开 Agent 测试任务，确认输入、工具调用、最终文本和业务结果。

提交前检查

  • [ ] 输入中的对象名称、编号和人员名称属于当前企业，且不直接依赖跨企业 ID。

  • [ ] 创建场景使用随机客户名、联系人名或手机号时，输入与预期结果引用同一个随机值。

  • [ ] 更新场景提供了正确的目标 data_id，并明确需要回查的字段。

  • [ ] 查询和聚合条件使用了正确的对象 API 名、字段 API 名和时间范围。

  • [ ] expected_result__c 是完整 JSON，validate_type 与场景一致。

  • [ ] 只有在确实需要校验时才填写 expected_tools、expected_skills 和 expected_agents。

  • [ ] loop.total 与该用例的实际预期调用复杂度相匹配。

  • [ ] 附件已经上传到执行环境可访问的 /opt/data/ 路径。

  • [ ] 已区分任务完成、业务校验通过和工具调用校验通过。
