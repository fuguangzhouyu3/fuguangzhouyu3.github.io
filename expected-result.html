编写预期结果

expected_result__c 是校验器使用的 JSON 配置。它描述预期的业务结果、工具调用、 Skill、子 Agent 和执行循环，不会作为用户问题直接发送给 Agent。

公共结构

以下结构展示常用字段。不同校验类型使用的业务字段不同，不要为了“字段齐全”而 把所有字段都复制到每条用例中。

{ "validate_type": "create", "expected_tools": [], "expected_skills": [], "expected_agents": [], "loop": { "total": 5 } }

字段

作用

validate_type

选择校验类型，例如 create、update、query 或 analysis。

expected_tools

期望 Agent 调用的关键工具，可以使用工具名或带 action 的对象。

expected_skills

期望命中的 Skill API 名列表。

expected_agents

期望命中的子 Agent 名列表，当前实现的主读取键。

loop.total

该用例允许或预期的循环次数，按实际链路复杂度填写。

当前实现还兼容 expected_sub_agents 和 expected_subAgents。新用例优先使用 expected_agents；如果历史数据使用兼容键，录入前按部署版本确认。

预期工具结构

CLI 场景

当工具调用按 API 名识别时，可以写：

{ "name": "sharecrm", "action": { "api_name": "QueryRecordsByFields" } }

按方法名识别时，可以写：

{ "name": "sharecrm", "action": { "method": "query-by-fields" } }

不要把展示文案当成 API 名；预期值应以实际工具调用中的结构化字段为准。

内置能力

DataAddAgent 常用的创建能力：

{ "expected_agents": [ "DataAddAgent" ], "expected_tools": [ "crm-record-create" ] }

DataEditAgent 常用的编辑能力：

{ "expected_agents": [ "DataEditAgent" ], "expected_tools": [ "crm-record-edit" ] }

完整工具示例

{ "expected_agents": [ "DataAddAgent" ], "expected_tools": [ { "name": "crm-record-create" }, { "name": "sharecrm", "action": { "api_name": "CreateRecordsByData" } } ], "loop": { "total": 5 } }

工具预期用于诊断 Agent 是否走了正确路径；它不能代替业务结果校验。

创建场景 create

单对象创建

{ "validate_type": "create", "object_api_name": "AccountObj", "object_display_name": "客户", "required_fields": [ { "api_name": "name", "value": "${random:company}", "field_type": "text", "match_mode": "exact" } ], "optional_fields": [], "details": [], "expected_skills": [ "data-add" ], "loop": { "total": 5 } }

required_fields 是必须满足的字段；optional_fields 用于补充校验或评分，是否 影响整体结果以当前校验器配置为准。

主从对象创建

{ "validate_type": "create", "object_datas": [ { "object_api_name": "SalesOrderObj", "object_display_name": "销售订单", "required_fields": [], "optional_fields": [], "details": [ { "SalesOrderProductObj": [ { "required_fields": [], "optional_fields": [] } ] } ] } ] }

主对象和明细对象的 API 名必须来自当前企业的对象描述，不能只使用页面显示名称。

多对象创建

{ "validate_type": "create", "object_datas": [ { "object_api_name": "AccountObj", "object_display_name": "客户", "required_fields": [], "optional_fields": [], "details": [] }, { "object_api_name": "ContactObj", "object_display_name": "联系人", "required_fields": [], "optional_fields": [], "details": [] } ] }

更新场景 update

更新场景最重要的是证明 Agent 修改了正确的记录。data_id 应引用目标记录的真实 ID 或由业务变量动态解析出的 ID。

{ "validate_type": "update", "object_datas": [ { "object_api_name": "ContactObj", "object_display_name": "联系人", "data_id": "${obj_data:ContactObj[测试联系人_id]}", "required_fields": [ { "api_name": "mobile1", "value": "replace-with-current-mobile", "display_value": "replace-with-current-mobile", "field_type": "text", "match_mode": "exact" } ], "optional_fields": [], "details": [] } ], "expected_agents": [ "DataEditAgent" ], "expected_tools": [ "crm-record-edit", { "name": "sharecrm", "action": { "api_name": "UpdateRecord" } } ], "loop": { "total": 8 } }

需要验证实际落库时，可以增加 CRM 回查配置：

{ "crm_readback_expect": { "object_data": [ { "field": "mobile1", "expected": "replace-with-current-mobile", "match_mode": "exact" } ] } }

工具调用成功、页面显示成功或最终文案正确，都不能单独证明目标记录已经正确落库； 需要通过回查目标对象和目标 ID 确认。

查询场景 query

查询场景通过 search_query_info 表达对象和过滤条件。该字段是 JSON 字符串， 字符串内部的动态变量会在执行时解析。

{ "validate_type": "query", "object_api_name": "ScheduleObj", "search_query_info": "{\"limit\":100,\"offset\":0,\"filters\":[{\"field_name\":\"begin_time\",\"field_values\":[${time:未来1天_timestamp}],\"operator\":\"LTE\"},{\"field_name\":\"end_time\",\"field_values\":[${time:明天0点_timestamp}],\"operator\":\"GTE\"},{\"field_name\":\"participants\",\"field_values\":[\"${employee:current_user}\"],\"operator\":\"HASANYOF\"}],\"orders\":[{\"fieldName\":\"begin_time\",\"isAsc\":true,\"isReference\":false}]}" }

写查询条件时检查：

  • object_api_name 是目标对象 API 名。

  • field_name 和 fieldName 符合当前接口结构。

  • 时间范围的起止边界符合业务含义。

  • 关联人员字段使用当前企业可解析的人员值。

  • 没有把展示名称误写成字段 API 名。

聚合场景 analysis

聚合场景使用 analysis_mode: "aggregation_compare"。agg_type 为 count 时 统计记录数，为 sum 时还需要填写 agg_field。

按字段求和

{ "validate_type": "analysis", "analysis_mode": "aggregation_compare", "aggregation": { "object_api_name": "NewOpportunityObj", "query": { "object_describe_api_name": "NewOpportunityObj", "search_query_info": "{\"limit\":100,\"offset\":0,\"filters\":[{\"field_name\":\"create_time\",\"field_values\":${time:本月_range},\"operator\":\"BETWEEN\"}],\"orders\":[{\"fieldName\":\"last_modified_time\",\"isAsc\":false}]}" }, "agg_type": "sum", "agg_field": "amount", "tolerance": 0.001 }, "expected_tools": [ { "name": "sharecrm", "action": { "api_name": "QueryRecordsAggregateBySQL" } } ], "loop": { "total": 4 } }

统计记录数

{ "validate_type": "analysis", "analysis_mode": "aggregation_compare", "aggregation": { "object_api_name": "AccountObj", "query": { "object_describe_api_name": "AccountObj", "search_query_info": "{\"limit\":10000,\"offset\":0,\"filters\":[{\"field_name\":\"create_time\",\"field_values\":${time:最近3个月_range},\"operator\":\"BETWEEN\"}]}" }, "agg_type": "count" }, "loop": { "total": 4 } }

聚合条件无法被准确执行时，不要用未过滤的列表结果代替严格聚合结果；应先确认 对象、字段和聚合接口是否支持该查询。

参考答案语义校验

已知正确答案且不需要实时回查列表时，可以使用 reference_answer_match：

{ "validate_type": "analysis", "analysis_mode": "reference_answer_match", "expected_answer": "生产/加工/制造：32；通信/电子/互联网：22；贸易/批发/零售/租赁业：17；商业服务：5；金融业：5", "expected_skills": [], "expected_tools": [], "tool_match_config": { "should_consider_order": false, "should_exact_match": false, "threshold": 0.5, "verbose_mode": false }, "loop": { "total": 8 } }

expected_answer 必须包含本次用例真正要求的业务事实。不要用过于宽泛的描述， 否则即使关键数字缺失也可能无法准确定位失败原因。

字段匹配方式

match_mode

含义

适用提示

exact

精确匹配。

ID、时间戳和固定文本优先使用。

contains

包含匹配。

适合允许附加文案的文本字段。

case_insensitive

忽略大小写的精确匹配。

适合英文大小写不稳定的字段。

contains_ci

忽略大小写的包含匹配。

适合英文片段或标签。

semantic

语义匹配。

需要接受同义表达时使用。

semantic_contains

语义包含匹配。

需要在长文本中判断关键含义时使用。

fuzzy

文本类字段的双向包含。

只适用于 text、long_text、rich_text 等文本字段。

常见错误

  • 用页面显示名称代替对象或字段 API 名。

  • 更新场景遗漏 data_id，导致无法证明修改目标。

  • 输入和预期结果各自生成了不同的随机值。

  • 聚合场景只校验最终回复数字，没有固定查询范围。

  • 只看 FINISHED 或 Agent 成功文案，没有核对业务校验和落库回查。

  • 用 expected_subagents 直接照抄历史模板，没有按当前版本确认实际读取键。
